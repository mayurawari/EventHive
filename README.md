# EventHive – Open Source Project Guide

**IMPORTANT:**  
EventHive already has a functioning web app and backend (including login/register flows). BEFORE making any changes, always review the current codebase and only extend or refactor components as required for new flows or optimizations described herein.

## Global Rules
- Leverage all existing logic, components, backend endpoints, and assets.
- Only modify or add code when required to implement new features or improve UX as outlined in the .md docs below.
- Maintain consistent use of open-source and free resources.
- All UI, animation, logic, and architecture must remain consistent with standards in `designing.md`, `frontend.md`, and `backend.md`.
- If unsure, start by thoroughly reviewing the respective code areas and adapt instead of duplicating logic.

**Refer to:**
- Backend logic and architecture: [`backend.md`](./backend.md)
- Frontend/component and app flows: [`frontend.md`](./frontend.md)
- Design, colors, animation, and UI rules: [`designing.md`](./designing.md)
